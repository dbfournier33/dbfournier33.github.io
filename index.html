Multi-Tenant Compliance-QA Platform

Built a stateless, multi-tenant SaaS that watches deadlines and pre-checks filings for regulated care providers — hard tenant isolation, a versioned rules engine, and minimal-PHI by design, verified end to end.

PostgreSQLrow-level securityNode/TSExpresszodHIPAA-aware
Read the build
What it doesA pre-submission QA layer that flags deadline and denial risk before anything reaches a state portal — it never files, and never stores the sensitive record.
What I built
  • Multi-tenant Postgres with FORCE row-level security + WITH CHECK isolation and security-invoker views; a versioned rules engine with validity windows.
  • A per-request, tenant-scoped API (Node/TS, Express, zod); a PHI-minimized schema — initials and dates only, never the record.
ResultTenant isolation and the rules engine verified against a real database — cross-tenant reads blocked, cross-tenant writes rejected. A reusable template: swap the rules and the buyer, the engine is unchanged.
